# 调度降级与重试

这里的降级是**调度执行方式替代**，不改变诊断能力、证据标准、字段和评分。

## 触发与动作

| 情况 | 动作 | 出口 |
| --- | --- | --- |
| 短暂超时、EAGAIN/EINTR、临时资源忙 | 同一步骤持续重试 | 产物校验成功后继续 |
| 脚本缺失 | blocked 并生成原步骤同结构工作模板 | 等价人工执行，校验后 resume |
| 已明确选择 `execution=manual_equivalent` | blocked 等待当前步骤人工产物 | 字段、输入指纹、附件哈希均通过才继续 |
| 路径/参数/编码错误、权限不足 | permanent，停止 | 修正条件后恢复 |
| 磁盘满、内存不足 | resource，持续重试 | 资源恢复且产物校验成功后继续 |
| 未识别执行错误 | unknown，停止 | 核对错误后重试或选择等价执行 |
| 分析材料缺失、未知场景、低可信度 | 正常记录证据缺口与结论限制 | 完成已有证据分析与报告 |

资源错误不会触发少读日志、少做分析或更低评分标准。等价执行使用当前已有材料，不能补采。
等价产物仍由原负责 skill 交付，不能用“手工完成”字样替代证据与实际输出。

## 持续重试

默认不设置重试次数上限。对 transient/resource 执行错误，runner 保留失败产物和证据，按指数退避持续尝试，直到该步骤产物通过契约校验。
`--retry-delay 2` 是退避起点，后续指数增加并受脚本上限约束。
永久配置错误、未知错误和用户中断不会自动重试，需修正条件后恢复。`blocked` 是等待 Agent 产物，不计执行失败；重复检查同一 blocked 模板不增长 attempt。

每次写 `artifacts/<同名.md>`，同一 state-dir下不互相覆盖。
失败也保留业务 `result` 的已有字段、证据、附属输出、`error` 和 `next_action`，不能只留错误 TXT/JSON。
失败尝试与后续成功不能互相覆盖。公共外壳见 [产物契约](pipeline-artifacts.md)。

## 有副作用步骤

`promote` 默认 `enabled=false`，输出 `promotion.md` 说明未执行写入。
启用时必须给出明确 `cases_dir`，先在隔离副本调用原入库工具，校验目标内容后提交，记录 mutation receipt。
恢复时核对 mutation_id、目标与内容哈希，已提交则不重复追加；不确定是否已提交时停止核对。
